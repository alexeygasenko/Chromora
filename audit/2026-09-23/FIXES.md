# Исправления по аудиту Chromora и тема Frutiger Aero

Дата: **23 сентября 2026**. Ветка: **`codex/full-audit-2026-09-23`**.

**Дополнение после проверки в живом браузере:** обнаружены и исправлены неправильный backend URL и ранний импорт модулей Wplace, пропущенные первоначальными fixtures. Актуальная сборка и результаты **55/55 тестов** описаны в [LIVE_BROWSER_FIX.md](LIVE_BROWSER_FIX.md). Числа и контрольные суммы ниже относятся к предшествовавшему снимку приемки; установленная копия в браузере ожидает ручного обновления.

Этот документ описывает изменения после [исходного аудита](REPORT.md). Исторический отчет и его диагностические результаты сохранены отдельно: они показывают состояние до исправлений и не являются результатами новых regression tests.

Работа выполнялась поверх существующего рабочего дерева. Изменения и материалы, которые уже находились в нем до начала исправлений, не следует автоматически считать результатом этой работы.

**Статус:** внесены исправления A01–A16 и дополнительных замечаний по устойчивости; добавлена отдельная тема Frutiger Aero. Локальная приемка завершена. Изменения находятся в рабочем дереве указанной ветки; удаленная публикация не выполнялась.

## Дополнительные исправления и условия совместимости

| Пункт исходного отчета | Текущее поведение и подтверждение |
|---|---|
| Null/malformed/foreign сообщения | Проверяются форма сообщения, отправитель и допустимые данные. Network regressions подтверждают, что посторонние payload не меняют identity/coordinates и не завершают чужой запрос тайла. |
| Таймеры и удаление окон | `Overlay` владеет таймерами и глобальными обработчиками; cleanup работает при `dispose()` и удалении DOM. Таймер не останавливается до первого mount. Main освобождает свои дочерние окна, SettingsManager — interval и запись hotkey. Проверены timer-before-mount, detach и освобождение окон. |
| Поврежденные settings | Нормализуются flags, highlight, фильтры, горячие клавиши, тема и оконная геометрия; здоровые неизвестные поля сохраняются. Восстановленные настройки сравниваются с реальным persisted input и записываются. Добавлены случаи неправильного типа theme и ошибка GM storage. |
| Без Web Locks | Изменение template storage останавливается до создания изображения/записи, если безопасная межвкладочная блокировка недоступна. Это явное ограничение совместимости: чтение и изменение хранения не следует считать одинаково доступными во всех окружениях. Проверено отсутствие побочных записей при таком отказе. |
| Синхронизация между вкладками | GM change listener и fallback через focus/visibility; события объединяются, актуальный storage перечитывается в очереди операций и повторно проверяется после декодирования. Sync не записывает снимки обратно. Проверены concurrent create/toggle/delete двух manager, запоздавшее событие, изменение storage во время decode, malformed storage и cleanup. Миграция приостанавливает sync и восстанавливает его в finally. |
| Yield без `scheduler.yield` | Fallback использует задачу с timeout вместо ожидания следующего animation frame; регрессия выполняется без scheduler и rAF. |
| ImageBitmap lifetime | Временные bitmap закрываются. Bitmap удаленного шаблона остается доступным уже работающему render до освобождения его ссылки; это проверено отдельно. |
| Стабильная схема хранения/bridge | Сборка сохраняет сериализуемые и внешние имена свойств. Для подтвержденных старых ключей `xi/Ci` предусмотрен перенос в `colorLayout/layoutSizes` только внутри нужной записи. Проверяются minifier/CSS mapping и контракт готового bundle. |
| Базовая доступность | Ячейки highlight имеют позицию и состояние в имени. Карточка цвета — группа с отдельными native кнопками. Окна получают/возвращают фокус; dragbar поддерживает стрелки и Home, resize — стрелки. Shift увеличивает шаг. Это проверка поведения в браузере, а не сертификация WCAG. |

Ошибки Settings показываются внутри окна. Ошибки сохранения геометрии также обрабатываются без необработанного Promise rejection; это проверено при принудительном отказе GM storage. Проверки с искусственным отказом GM полезны для завершенности UI, но не моделируют все причины отказа конкретного userscript manager.

## Новая тема Frutiger Aero

В Settings → Appearance добавлен четвертый вариант **Frutiger Aero**. Он использует голубые стеклянные поверхности, глянцевые кнопки, зеленые акценты и отдельную типографику. Выбор сохраняется и распространяется на окна, сообщения и управляющие элементы Chromora.

Основной текст — **PT Sans 400/700**, заголовки — **Exo 2 600–700**. Для обоих семейств включены Latin/Cyrillic WOFF2. Файлы находятся в `build/assets/aero/`; manifest фиксирует семейство, диапазон символов, начертание, источник и размер. Лицензии включаются в поставляемый userscript.

Шрифты интерфейса **Michroma/Rajdhani** также включены локально через `build/assets/interface/`; имеющийся Roboto Mono сохраняется. Браузерные тесты загрузили Aero-шрифты из встроенных данных при заблокированной внешней сети и проверили выбранные font-family. Сайт/CDN не нужен для их загрузки во время работы userscript.

Размер поставки увеличивается осознанно:

| Добавленные наборы | WOFF2-файлы | Байты WOFF2 | Байты Base64 без обертки CSS |
|---|---:|---:|---:|
| Aero: Exo 2 + PT Sans | 6 | 211 916 | 282 560 |
| Прежний интерфейс: Michroma + Rajdhani | 5 | 79 388 | 105 856 |
| **Всего этих двух наборов** | **11** | **291 304** | **388 416** |

Эти суммы не включают имеющийся Roboto Mono, CSS, код и текст лицензий. Поэтому рост размера JS-файла нельзя интерпретировать как рост объема пиксельного readback или как регрессию частоты кадров.

Визуально проверенные снимки из изолированной браузерной fixture: [desktop](../../tests/evidence/frutiger-aero-desktop.png), [mobile](../../tests/evidence/frutiger-aero-mobile.png). Это реальные компоненты приложения с тестовыми данными.

## Сборка и поставка

Validation job запускает чистую установку, тесты, аудит зависимостей, сборку, проверку bundle и генерацию документации. Публикация запускается отдельно после успешной проверки, привязана к исходному SHA и проверяет целостность подготовленных артефактов. Commit messages используются как данные. Параллельные публикации ограничены workflow concurrency; тестируется отказ публикации при изменившемся main.

Обе сборки выполнены из одного финального снимка кода. Режим CI проверялся в отдельной временной копии после чистого `npm ci`.

## Границы приемки

Тесты запускаются в изолированных fixtures с управляемыми GM, fetch и bridge; часть проверок использует настоящие DOM, ResizeObserver, Canvas, PNG и браузерный механизм шрифтов. Они не отправляют рисунки на Wplace и не меняют пользовательское GM-хранилище рабочего сайта.

Остаются проверки интеграции, для которых нужны отдельные фактические результаты:

- Текущий live Wplace/MapLibre и его внутренние API обновления растров, worker/service-worker сообщения, изменения DOM сайта.
- Конкретные версии Tampermonkey/Violentmonkey, реальные внешние storage notifications, две настоящие вкладки и их перезагрузка.
- Pointer/touch на мобильном устройстве, реальные screen readers и высокая нагрузка на больших наборах шаблонов.
- Отправка подготовленных областей через реальный Paint-процесс и поведение сетевого сервиса при ошибках.

Без этих данных нельзя объявлять совместимость со всеми версиями сайта и userscript managers, отсутствие любых багов либо гарантированный прирост FPS. Подтвержденные результаты этого документа ограничены перечисленными кодовыми изменениями и воспроизводимыми тестами.
