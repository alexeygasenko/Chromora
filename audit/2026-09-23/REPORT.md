## Проблемы P1

### A01. Обычный пропуск прозрачных тайлов удаляет непустые участки шаблона

**Код:** [Template.js:321](<E:/Coding/Blue Marble/src/Template.js:321>), пропуск chunk — [Template.js:158](<E:/Coding/Blue Marble/src/Template.js:158>), default настройки — [templateManager.js:825](<E:/Coding/Blue Marble/src/templateManager.js:825>).

Проверка прозрачности уменьшает изображение до 10×10 после нескольких сдвигов. Такая выборка может не захватить отдельный непрозрачный пиксель. Обычный режим, включенный по умолчанию, получает false и выбрасывает весь chunk.

**Воспроизведение:** настоящий PNG 1000×1000, прозрачный фон, один белый пиксель `(500,500)`, skip-transparent включен, aggressive выключен. В Edge `pixelCount.total=1`, но число сохраненных chunks **0 вместо 1**. Пиксели `(100,100)` и `(999,999)` тоже теряются; `(0,0)` в контрольном случае сохраняется.

**Последствие:** части изображения исчезают уже при создании и не попадают в сохраненный шаблон. Счетчики расходятся с тем, что можно отрисовать.

**Исправление и приемка:** точная проверка alpha исходного прямоугольника, предпочтительно по уже имеющемуся ImageData. Проверить sparse PNG с одиночными пикселями по всей площади и границам. Оптимизация не должна менять набор сохраняемых непрозрачных пикселей.

### A02. При перекрытии шаблонов подготовка области выбирает нижний цвет

**Код:** [templateManager.js:266](<E:/Coding/Blue Marble/src/templateManager.js:266>), [templateManager.js:360](<E:/Coding/Blue Marble/src/templateManager.js:360>), [templateManager.js:1424](<E:/Coding/Blue Marble/src/templateManager.js:1424>).

Отрисовка рисует шаблон с большим `sortID` поверх предыдущего. Area selection обходит шаблоны в другом порядке и после выбора первой координаты отбрасывает следующие совпадения.

**Воспроизведение:** нижний шаблон красный, верхний зеленый, под ними пустой пиксель. На карте виден зеленый; `findTemplatePixelRuns` в режиме `template` возвращает красный.

**Последствие:** подготовленный черновик не соответствует видимому изображению. Пользователь может отправить неправильный цвет через кнопку Paint. Сам аудит отправку пикселей не выполнял.

**Исправление и приемка:** единая модель верхнего непрозрачного пикселя для renderer и selection. Цветовой фильтр применять после разрешения перекрытий. Проверить прозрачный верхний слой, несколько слоев и одинаковые `sortID`.

### A03. Перехват изображений оставляет fetch незавершенным

**Код:** [main.js:1061](<E:/Coding/Blue Marble/src/main.js:1061>), [main.js:1072](<E:/Coding/Blue Marble/src/main.js:1072>), [apiManager.js:182](<E:/Coding/Blue Marble/src/apiManager.js:182>), [main.js:1233](<E:/Coding/Blue Marble/src/main.js:1233>).

Hook перехватывает почти любые `image/*` ответы, тогда как consumer отвечает только для `tile/tiles`. Для обычного PNG через fetch ответа на bridge-запрос не будет. Ошибка renderer имеет тот же результат: async event handler отклоняется, оригинальный fetch остается pending. Timeout и возврат исходного изображения отсутствуют. Listener также устанавливается после длительного импорта, что оставляет окно потери сообщений при запуске.

**Воспроизведение:** контрольный tile завершается; `/assets/avatar.png` остается pending без вызова renderer; tile с принудительным decode failure остается pending с ошибкой handler. Проверено отсутствие последующего terminal path по коду. Обычная загрузка через `<img>` этим тестом не охвачена.

**Последствие:** тайл/ресурс сайта не загружается до перезагрузки, запись остается в очереди. Ошибка расширения блокирует успешный исходный ответ сайта.

**Исправление и приемка:** строгий allowlist URL тайлов, установка consumer до импорта, timeout/отмена, fallback к исходному Response и очистка очереди во всех исходах. Проверить unsupported images, decode/encode failure, disabled mode, старт с большим шаблоном и отмену запроса.

### A04. Миграция sparse-шаблона сдвигает изображение на целый тайл

**Код:** [Template.js:360](<E:/Coding/Blue Marble/src/Template.js:360>), [templateManager.js:1306](<E:/Coding/Blue Marble/src/templateManager.js:1306>), [WindowWizard.js:309](<E:/Coding/Blue Marble/src/WindowWizard.js:309>).

Начало координат вычисляется двумя несовместимыми способами. `calculateCoordsFromChunked` берет X первого тайла верхнего ряда. Сборка PNG берет минимальный абсолютный X по всем рядам. При пропущенном прозрачном верхнем левом участке эти начала различаются.

**Воспроизведение:** chunks `0011,0010,000,000` и `0010,0011,000,000`. Метод координат возвращает `[11,10,0,0]`; bounding origin PNG — `[10,10,0,0]`. Wizard передает первое значение при создании из второго изображения, получая сдвиг **+1000 px по X**.

**Доказательность:** сам выбор координат выполнен реальным методом; прохождение результата через миграцию проверено по цепочке вызовов. Полная PNG-миграция в браузере отдельно не исполнялась.

**Исправление и приемка:** возвращать PNG и его абсолютное начало из одной операции. Сравнивать абсолютные координаты непрозрачных пикселей до/после миграции L-образных и других sparse fixtures.

### A05. Текст сообщения коммита исполняется shell в CI

**Код:** [build.yml:155](<E:/Coding/Blue Marble/.github/workflows/build.yml:155>), [build.yml:182](<E:/Coding/Blue Marble/.github/workflows/build.yml:182>).

TITLE/BODY вставляются GitHub expressions непосредственно внутрь shell-команды `git commit`. Двойные кавычки не запрещают command substitution и могут быть закрыты содержимым сообщения.

**Воспроизведение:** безвредный TITLE с `$(printf CI_INJECTION_PROOF >&2)` в локальной bash-проверке фактической workflow-строки исполнил `printf`. Вместо git использовалась заглушка; никакой удаленный workflow, секрет или репозиторий не затрагивался.

**Условия и последствия:** workflow запускается на push в main, поэтому требуется попадание такого сообщения в main; это не утверждение о доступной любому внешнему PR атаке. Job имеет `contents:write`, следовательно выполнение подставленного shell-кода угрожает артефактам и содержимому репозитория. Случайные shell-символы также могут ломать обычную сборку.

**Исправление и приемка:** передавать текст через environment и файл сообщения (`git commit -F`), не вставлять его в исполняемый script. Проверить кавычки, `$()`, backticks и многострочные сообщения как обычные данные.

## Функциональные ошибки и проблемы производительности P2

### A06. Старый рендер перезаписывает актуальное состояние пикселя

**Код:** [templateManager.js:1489](<E:/Coding/Blue Marble/src/templateManager.js:1489>), [templateManager.js:1613](<E:/Coding/Blue Marble/src/templateManager.js:1613>), [templateManager.js:2181](<E:/Coding/Blue Marble/src/templateManager.js:2181>).

Два параллельных рендера одного chunk безусловно записывают `pixelStateByChunk` и `pixelCount.correct`. Задержанный старый decode может закончиться последним. В управляемом воспроизведении новый пустой пиксель получает state 2, затем старый ответ заменяет его на state 1. Выделение возвращает **0 вместо 1** доступного пикселя.

Нужна версия запроса/тайла и запрет устаревшего commit, включая статистику. Приемка — детерминированные сценарии обоих порядков завершения и смены/удаления шаблона во время рендера.

### A07. Каждый затронутый тайл имеет большую фиксированную стоимость

**Код:** [templateManager.js:1491](<E:/Coding/Blue Marble/src/templateManager.js:1491>), [templateManager.js:1540](<E:/Coding/Blue Marble/src/templateManager.js:1540>), [templateManager.js:1893](<E:/Coding/Blue Marble/src/templateManager.js:1893>).

Даже шаблон 1×1 вызывает `getImageData(3000×3000)` — **36 000 000 B** readback. Для полного chunk дополнительно копируются **36 000 000 B** и выделяется **1 000 000 B** состояния. Получается около **73 MB рабочих JS-буферов** сверх существующих данных шаблона и графических ресурсов. Это размеры TypedArray, а не измеренная физическая RAM; часть состояния затем остается в кеше. Одновременные рендеры не ограничены.

| Шаблон на тайле 1000×1000 | Первый вызов | Следующие три вызова |
|---|---:|---|
| 1×1 | 92,7 ms | 29,1 / 49,0 / 29,8 ms |
| 1000×1000 | 76,1 ms | 54,1 / 57,0 / 60,6 ms |

Замеры сделаны настоящим Edge/Canvas/PNG с белой картой, отключенной подсветкой и логами. Второй сценарий запускался в уже прогретом процессе. Это elapsed time операции, **не длительность непрерывной блокировки main thread и не FPS Wplace**.

Рекомендуется анализировать board в исходном масштабе, читать только нужную область, хранить логические цвета компактнее, копировать только изменяемые данные и ограничить параллельность. После изменения сравнивать изображения и статистику с эталоном; отдельно измерить long tasks и пик памяти на реальном наборе шаблонов.

### A08. Выбор координат сбрасывает геометрию Filter

**Код:** [WindowTemplateCoordinates.css:3](<E:/Coding/Blue Marble/src/WindowTemplateCoordinates.css:3>), [WindowFilter.js:1065](<E:/Coding/Blue Marble/src/WindowFilter.js:1065>), [WindowFilter.js:1142](<E:/Coding/Blue Marble/src/WindowFilter.js:1142>).

### A10. На свежих настройках Cross выглядит выбранным, но не включается

### A14. Разные неизвестные цвета считаются одинаковыми

**Код:** [templateManager.js:1993](<E:/Coding/Blue Marble/src/templateManager.js:1993>), [templateManager.js:2128](<E:/Coding/Blue Marble/src/templateManager.js:2128>).

Неизвестный цвет board и неизвестный цвет template оба получают ID `−2`. Сравнение ID дает ложное совпадение: `0xff123456` и `0xffabcdef` в воспроизведении дают **1 correct вместо 0**. Частота зависит от наличия off-palette/нестандартных alpha в реальных данных.

`Other` должен оставаться категорией, а не доказательством равенства. Сравнивать исходные цвета по выбранной политике либо явно исключать неподдерживаемые цвета из correct.

### A15. Ошибка миграции оставляет Wizard на экране Loading

**Код:** [WindowWizard.js:162](<E:/Coding/Blue Marble/src/WindowWizard.js:162>), [WindowWizard.js:243](<E:/Coding/Blue Marble/src/WindowWizard.js:243>). Полная цепочка описана в UI-08 [приложения по интерфейсу](<E:/Coding/Blue Marble/audit/2026-09-23/ui/REPORT.md>).

Обработчик запускает асинхронную миграцию и переключает UI на загрузку, но не предоставляет полноценный terminal error path при отказе операции. Ошибки декодирования, GM storage или конфликта с другой вкладкой могут оставить загрузочный экран без результата.

Это вывод по обработчикам и обработке rejection; полный browser end-to-end с отказом GM отдельно не выполнялся. Нужны try/catch/finally, текст причины, безопасный retry/cancel и сохранение rollback-поведения.

## Менее срочные дефекты и условные риски

1. **P3, null message.** [main.js:52](<E:/Coding/Blue Marble/src/main.js:52>) деструктурирует `event.data`, [apiManager.js:67](<E:/Coding/Blue Marble/src/apiManager.js:67>) обращается к полю до проверки. Постороннее сообщение `null` воспроизводимо дает две TypeError. Проверять тип и форму до чтения полей.
2. **P3, таймеры.** Таймер Overlay продолжает interval после отсоединения time-element; SettingsManager также не владеет cleanup своего interval. Это подтвержденный недостаток lifecycle при удалении/неудачной инициализации, не доказательство утечки при каждом открытии Filter. Filter и Templates свои основные таймеры очищают.
3. **Поврежденные settings.** Валидный JSON `{flags:{}}` проходит общий loader и ломает `toggleFlag`/Settings. Путь, которым штатный UI создал бы такой JSON, не найден. Добавить структурный normalizer flags/highlight/window state с defaults.
4. **Нет Web Locks.** Два manager одновременно создают шаблоны, GM writes задержаны; без `navigator.locks` остается **1 запись вместо 2**. При общем lock обе записи сохраняются. Это условная совместимость fallback-окружения, не воспроизведенная потеря данных в современном Edge с Web Locks. Также сохраненные изменения другой вкладки автоматически не синхронизируют ее runtime-массив до перезагрузки.
5. **rAF fallback.** Без `scheduler.yield` scan ждет `requestAnimationFrame`; удержанный callback в тесте удерживает render. В проверенном Edge scheduler имеется. Для фоновых вкладок/других браузеров нужен task-based fallback и проверка отмены. См. [поведение requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).
6. **ImageBitmap lifetime.** За 20 mock-render вызовов создано 20 временных bitmap, `close()` вызван 0 раз. Постоянная утечка RAM/VRAM не доказана; GC может освобождать ресурсы. Предпочтительно явно закрывать временные bitmap в finally. См. [ImageBitmap.close](https://developer.mozilla.org/en-US/docs/Web/API/ImageBitmap/close).
7. **Граница postMessage.** Синтетический foreign-origin `/me` payload меняет userID обработчика; origin/source не проверяются согласованно. Реальный opener/iframe/COOP и удаленная достижимость не проверены, поэтому здесь не заявляется готовый внешний exploit. Валидировать sender, schema, endpoint и диапазоны значений.
8. **Межрелизный storage contract.** Terser меняет некоторые persisted keys, например `colorLayout/layoutSizes`. Проверены текущий dist, local/CI и пять исторических dist версий 1.1.0–1.3.0: во всех mapping одинаковый (`xi/Ci`), восемь переходов сохранили горизонтальный режим и геометрию. **Несовместимость не подтвердилась.** Стабильную сериализуемую схему все равно полезно закрепить, чтобы будущая смена mapping не превратилась в регрессию.

## Качество поставки, сопровождение и доступность

- В package.json отсутствуют штатные команды test/lint. До аудита regression tests в дереве не обнаружены. Диагностические сценарии этого аудита проверяют наличие текущих дефектов; их успешное завершение **не означает**, что продукт исправлен.
- Build workflow запускается после push в main; CodeQL на PR есть, однако PR build/runtime gate отсутствует. Добавить сборку и smoke до merge.
- Общие ветки `auto/wiki`, force-reset и отсутствие concurrency создают риск пересечения двух release runs. Кроме того, текущий `origin/main` может отличаться от SHA исходного события. Закрепить каждый артефакт за SHA и сериализовать публикацию. Реальная гонка двух GitHub Actions runs не запускалась.
- В CI используется `npm install`; для воспроизводимости основного build нужен `npm ci`. Генерация docs дополнительно устанавливает пакеты отдельно, что требует собственной фиксации версий.
- Обфускация затрагивает почти все unquoted properties, CSS mangler — в том числе строки протокола с `bm-`. Добавить проверку готового bundle и round-trip storage между версиями; отделить внешние контракты от внутренних имен.
- Важные зависимости от внутреннего MapLibre/Wplace runtime, DOM-селекторов и service-worker сообщений требуют интеграционных smoke после обновлений сайта. Изолированная fixture их не заменяет.
- Accessibility: названия девяти клеток highlight не объясняют их позицию; color-card имеет button-role с вложенными кнопками; для большинства окон нет общей политики переноса/возврата фокуса, keyboard drag/resize. Это результаты проверки кода, не screen-reader тест и не сертификация WCAG.
- Сайт аккуратно обрабатывает недоступность localStorage, имеет keyboard theme/menu/tabs и соответствующие ARIA-state. Локальные ресурсы и ID-связи прошли проверку.

## Что работает корректно в проверенном объеме

- Очередь mutations сохраняет порядок create/toggle/delete внутри runtime.
- При общем Web Lock два конкурирующих create сохраняют обе записи и разные ID.
- Испорченный persisted JSON не перезаписывается созданием нового шаблона.
- Отказ `GM.setValue` не добавляет несохраненный template в runtime array.
- У Color Filter есть owner, cleanup observer/listeners/debounce и единственный refresh interval; бесконечная утечка этого окна не подтверждена.
- Template Coordinates освобождает свои subscriptions/listeners и возвращает видимость окон; проблема геометрии возникает в persistence самого Filter.
- Pixel scan уступает управление порциями; UI-события статистики объединяются; area selection ограничивает число пикселей и поддерживает AbortSignal.
- В просмотренных путях названия шаблонов выводятся через textContent; подтвержденный XSS или исполнение импортируемого PNG/JSON не обнаружены. Это ограниченный вывод по просмотренным путям.
